# MCP tools

_For developers and attendees who want the detail: every tool the Compass MCP server offers, what each one reads or changes, which ones may be approved automatically, the command line and the environment variables._

The Compass [MCP server](Glossary#mcp-server) is the npm package `reinvent-compass`. It registers exactly the 24 tools keyed in [packages/contracts/src/mcp-tools.ts](https://github.com/henniefrancis/aws-re_invent-compass/blob/develop/packages/contracts/src/mcp-tools.ts). Each tool's class and wording live in [tool-registry.ts](https://github.com/henniefrancis/aws-re_invent-compass/blob/develop/packages/mcp-server/src/server/tool-registry.ts) and [descriptions.ts](https://github.com/henniefrancis/aws-re_invent-compass/blob/develop/packages/mcp-server/src/server/descriptions.ts).

## Tool classes

| Class        | Count | Meaning                                                                                                     | MCP annotations         |
| ------------ | ----- | ----------------------------------------------------------------------------------------------------------- | ----------------------- |
| Read         | 8     | Reads the catalog, your schedule, your folders or your GitHub, and changes nothing.                         | `readOnlyHint: true`    |
| Write        | 10    | Makes a real change: to your re:Invent schedule, or on the Compass pass service.                            | `destructiveHint: true` |
| Local action | 6     | Acts only on this machine or in your browser: sign-in, a plan file, a calendar file, the GitHub connection. | neither                 |

Five of the write tools change your real re:Invent schedule. In live mode they are [read-only](Glossary#read-only-mode) by default: they answer what they would do and change nothing until you set `COMPASS_ALLOW_WRITES=1` (see [Read-only by default](Read-Only-By-Default)). Write tools run one at a time, and each one reads your schedule again when its turn comes. Wherever a tool takes a session id, it also accepts a [session code](Glossary#session-code) such as `SVS339`.

## The 24 tools

| Tool                        | Class        | Changes your schedule | Inputs                                                                                                                    | What it does                                                                                                                                                                                                                                                      |
| --------------------------- | ------------ | --------------------- | ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sign_in`                   | Local action | No                    | `force?` (boolean)                                                                                                        | Signs in to the AWS Events service with your [AWS Builder ID](Glossary#aws-builder-id) in the browser ([PKCE](Glossary#pkce)). Reports only whether you are signed in and when it expires, never a token.                                                         |
| `sign_out`                  | Local action | No                    | none                                                                                                                      | Revokes the refresh token, clears the stored tokens and gives the Builder ID sign-out link.                                                                                                                                                                       |
| `refresh_catalog`           | Read         | No                    | `force?` (boolean)                                                                                                        | Downloads every page of the session catalog into the local cache and reads the event window.                                                                                                                                                                      |
| `find_sessions`             | Read         | No                    | `query?`, `filters?` (`services?`, `level?`, `type?`, `day?`), `limit?`                                                   | Searches the cached catalog by words, service, level, type or day. `limit` defaults to 20 and is capped at 50.                                                                                                                                                    |
| `scan_repo`                 | Read         | No                    | `path`                                                                                                                    | Scans a local folder read-only (one project, or a dev folder of git repositories) for the AWS services it uses and how deeply, and for other technology. Adds the result to your [tech list](Glossary#tech-list). Only names, depth and counts leave the scanner. |
| `plan_week`                 | Local action | No                    | `goals?` (strings), `level?`, `maxPerDay?`                                                                                | Suggests a week of sessions from your last scan, your goals and your confirmed schedule, and writes it as a [Kiro spec](Glossary#kiro-spec) in your workspace after you confirm the folder. Books nothing.                                                        |
| `check_itinerary`           | Read         | No                    | `commitments` (list of reserved sessions or personal time)                                                                | Checks a proposed itinerary against the [guardrail](Glossary#guardrail) and your schedule, and reports clashes and [tight connections](Glossary#tight-connection).                                                                                                |
| `show_schedule`             | Read         | No                    | none                                                                                                                      | Lists your reserved sessions, your [standby](Glossary#standby) list and your [layovers](Glossary#layover), each with the id the write tools take.                                                                                                                 |
| `reserve_with_guardrails`   | Write        | Yes                   | `sessionIds` (1 to 10, no duplicates)                                                                                     | Reserves sessions after the guardrail passes, then reads your schedule back to confirm.                                                                                                                                                                           |
| `cancel_reservation`        | Write        | Yes                   | `sessionId`                                                                                                               | Cancels one reservation. When it is part of a planned swap to a [repeat](Glossary#repeat), it runs the [safe swap](Glossary#safe-swap), so you are never left without a seat.                                                                                     |
| `add_standby`               | Write        | Yes                   | `sessionIds` (1 to 10, no duplicates)                                                                                     | Adds sessions to your standby list (favourites) as backups.                                                                                                                                                                                                       |
| `remove_standby`            | Write        | Yes                   | `sessionId`                                                                                                               | Removes one session from your standby list.                                                                                                                                                                                                                       |
| `add_layover`               | Write        | Yes                   | `action`: `create` with `personalTime`; `update` with `personalTimeId` and `personalTime`; `delete` with `personalTimeId` | Creates, changes or deletes a layover: a block of your own time for a meal or rest. `personalTime` is `startDateTime`, `endDateTime`, `title`, `description` and `location?`.                                                                                     |
| `issue_all_boarding_passes` | Write        | No                    | none                                                                                                                      | Issues an unofficial [boarding pass](Glossary#boarding-pass) for every reserved session in one call. Approving the call is the one confirmation.                                                                                                                  |
| `issue_boarding_pass`       | Write        | No                    | `sessionId?`                                                                                                              | Issues one boarding pass for one reserved session. Without `sessionId`, Compass asks which session.                                                                                                                                                               |
| `send_to_phone`             | Write        | No                    | `sessionIds?` (up to 80), `show?` (`link`, `qr` or `both`)                                                                | Creates a 15-minute [hand-off](Glossary#hand-off) to your phone as a link, a QR code on a page in your browser, or both. Without `show` it creates nothing and asks.                                                                                              |
| `sync_passes`               | Write        | No                    | `sessionIds?` (up to 80)                                                                                                  | Brings your passes in line with your confirmed schedule: issues, updates and [voids](Glossary#void) passes. It asks before any change, and voiding all passes or more than five needs an explicit confirmation.                                                   |
| `export_calendar`           | Local action | No                    | `commitments?`                                                                                                            | Builds a calendar file from your live schedule, or from the commitments you pass in. Books nothing.                                                                                                                                                               |
| `forget_me`                 | Write        | No                    | `confirm` (must be `true`)                                                                                                | Voids your passes and deletes your server records, then deletes the local schedule snapshot, tech list, GitHub sign-in and QR page.                                                                                                                               |
| `show_my_tech`              | Read         | No                    | `top?`                                                                                                                    | Lists your tech list on this machine: AWS services first, with depth, then languages, frameworks and tools, and how many folders and repositories it came from.                                                                                                   |
| `find_sessions_by_tech`     | Read         | No                    | `tech?`, `limit?`                                                                                                         | Finds cached catalog sessions on one technology, or on your most used technology when none is given.                                                                                                                                                              |
| `connect_github`            | Local action | No                    | none                                                                                                                      | Starts the device sign-in for the read-only Compass [GitHub App](Glossary#github-app) and shows the code to enter on GitHub.                                                                                                                                      |
| `scan_github`               | Read         | No                    | `owners?`, `includeForks?`, `maxRepositories?` (1 to 200, default 50)                                                     | Scans your GitHub repositories read-only, after you confirm the list, and adds what they use to your tech list. No code is saved.                                                                                                                                 |
| `disconnect_github`         | Local action | No                    | none                                                                                                                      | Deletes the GitHub sign-in held on this machine. Your tech list stays until `forget_me`.                                                                                                                                                                          |

A `commitment` is either `{ kind: "reservedSession", sessionId, startsAt, endsAt, title?, venue? }` or `{ kind: "personalTime", title, startsAt, endsAt, personalTimeId?, location? }`. Inputs are parsed with the contract schema: a field of the wrong type is refused, not coerced, and unknown fields are dropped. [Events API coverage](Events-API-Coverage) shows which Events API operation each tool calls, and [Pass API](Pass-API) lists the pass operations.

## Approval rules

Your [MCP client](Glossary#mcp-client) asks you before it runs a tool, unless you tell it to approve that tool automatically. The rules, from [power/POWER.md](https://github.com/henniefrancis/aws-re_invent-compass/blob/develop/power/POWER.md):

- **Only three tools may be auto-approved:** `refresh_catalog`, `find_sessions` and `check_itinerary`. They read the catalog or check a plan and touch nothing of yours.
- **Approve every other read each time.** `scan_repo` reads a folder of yours. `show_schedule` reads your schedule. `show_my_tech` and `find_sessions_by_tech` read your tech list. `connect_github`, `scan_github` and `disconnect_github` touch your GitHub account, and `scan_github` also asks you to confirm the repositories first.
- **Never auto-approve a write tool:** `reserve_with_guardrails`, `cancel_reservation`, `add_standby`, `remove_standby`, `add_layover`, `issue_all_boarding_passes`, `issue_boarding_pass`, `send_to_phone`, `sync_passes` or `forget_me`. `sync_passes` can void passes, so it is a write tool.
- **One approval for all passes.** For passes for every reserved session, the agent calls `issue_all_boarding_passes` once. Approving that call is the only confirmation; it never issues one pass per call.

Where the client supports MCP elicitation, the schedule tools, `sync_passes` and `forget_me` also ask you to confirm the exact change inside the tool; the two pass-issuing tools do not ask again. The description of every tool that changes your schedule says: "This changes your real re:Invent schedule. Compass checks it first and asks you to approve it."

Do not add the write tools of the official remote `awsevents` MCP server to your agent: they skip the guardrail. See [Events API coverage](Events-API-Coverage#the-official-remote-mcp-server).

## Command line

From [run-cli.ts](https://github.com/henniefrancis/aws-re_invent-compass/blob/develop/packages/mcp-server/src/cli/run-cli.ts):

| Command                                | What it does                                                                                                                                                                                                                                          | Exit code               |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| `reinvent-compass`                     | Starts the Compass server on stdio. This is what the Power's [mcp.json](https://github.com/henniefrancis/aws-re_invent-compass/blob/develop/power/mcp.json) runs, as `npx --yes reinvent-compass@0.1.0`.                                              | 1 if it cannot start    |
| `reinvent-compass demo [--repo <dir>]` | Runs the ten-step demo in [simulated mode](Glossary#simulated-mode), with no network and no sign-in. `--repo` scans a copy of your folder instead of the sample repo.                                                                                 | 1 if a step fails       |
| `reinvent-compass hook <name>`         | What a [Kiro hook](Glossary#kiro-hook) calls. `<name>` is `pre-write-guardrail` or `post-write-sync`. It reads the hook input from stdin (at most 1 MiB in 5 seconds), starts no shell and no subprocess, and fails open when it cannot judge a call. | 2 to block, otherwise 0 |
| `reinvent-compass --version`, `-v`     | Prints the version.                                                                                                                                                                                                                                   | 0                       |
| `reinvent-compass --help`, `-h`        | Prints the usage.                                                                                                                                                                                                                                     | 0                       |

Any other command prints the usage and exits 1.

`pre-write-guardrail` runs the same guardrail check as the server against the last confirmed schedule and the cached catalog, with no network. It blocks a `reserve_with_guardrails` call the guardrail blocks, and any call to one of the seven write tools of the official `awsevents` server. `post-write-sync` prints a one-line reminder to run `sync_passes` after a schedule change. The Power's hook template uses only `pre-write-guardrail`; see [Kiro Power](Kiro-Power).

## Environment variables

Read from the environment by [packages/mcp-server/src](https://github.com/henniefrancis/aws-re_invent-compass/tree/develop/packages/mcp-server/src) and [packages/core/src](https://github.com/henniefrancis/aws-re_invent-compass/tree/develop/packages/core/src):

| Variable                     | Effect                                                                                                                                                                                                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `COMPASS_MODE`               | `simulated` runs on made-up data: the synthetic catalog, a signed-in attendee and an in-process pass service, with no network. Any other value, or none, is live mode.                                                                                           |
| `COMPASS_ALLOW_WRITES`       | `1` turns writes on in live mode, so the five schedule tools can change your real schedule after you approve each change. Any other value keeps live mode read-only. Simulated mode always allows its made-up bookings.                                          |
| `COMPASS_ALLOW_SIMULATED`    | `1` allows simulated mode when `NODE_ENV` is `production`. Without it, simulated mode refuses to start there.                                                                                                                                                    |
| `COMPASS_API_URL`            | Replaces the built-in Compass API base URL (`https://reinvent-compass.vegas`), but only together with `COMPASS_ALLOW_API_OVERRIDE=1`. It must be https. Compass then prints a warning naming the host, and the pass client sends the ID token only to that host. |
| `COMPASS_ALLOW_API_OVERRIDE` | `1` lets `COMPASS_API_URL` take effect. On its own, `COMPASS_API_URL` is ignored.                                                                                                                                                                                |
| `COMPASS_GITHUB_CLIENT_ID`   | Replaces the client id of the Compass GitHub App, for a self-hosted app. Compass prints a warning that it cannot check the other app is read-only. An empty or malformed value turns GitHub scanning off.                                                        |
| `COMPASS_GITHUB_APP_SLUG`    | Replaces the app slug used for the install link `https://github.com/apps/<slug>/installations/new`.                                                                                                                                                              |

Owner-only test variables: `COMPASS_LIVE_TESTS`, `COMPASS_LIVE_CONFIRM` and `COMPASS_LIVE_SESSION_ID` gate the live smoke tests; see [Build and test](Build-and-Test#live-tests-owner-only).

The names `COMPASS_API_BASE_URL`, `COMPASS_WRITE_TOOLS` and `COMPASS_SERVER` also appear in the source, but as constants, not environment variables: setting them changes nothing.
